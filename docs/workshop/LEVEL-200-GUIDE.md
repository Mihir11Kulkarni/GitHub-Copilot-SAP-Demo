## 🧠 PROMPT ENGINEERING MASTERY

### Advanced Prompt Patterns

#### 1. **Chain-of-Thought Prompting**
Transform complex business requirements into working code through structured reasoning.

**Example: Complex Business Rule Implementation**
```
🎯 PROMPT:
"I need to implement a dynamic pricing algorithm for SAP products. Let me break this down:

1. First, analyze the business context:
   - Products have base prices, seasonal adjustments, and volume discounts
   - Pricing rules vary by customer segment and region
   - Integration with SAP ECC pricing conditions is required

2. Then, design the solution architecture:
   - CAP service with configurable pricing engine
   - Integration points with SAP standard pricing
   - Audit trail for price changes

3. Finally, implement with these constraints:
   - Performance: <100ms response time
   - Security: Price manipulation protection
   - Maintainability: Rule changes without code deployment

Generate the complete solution with this reasoning chain."
```

**Advanced Output:**
```typescript
// 1. Business Context Analysis (Generated by Copilot)
interface PricingContext {
  product: Product
  customer: Customer
  region: Region
  volume: number
  seasonalFactors: SeasonalFactor[]
}

// 2. Architecture Design
class DynamicPricingEngine {
  private ruleEngine: PricingRuleEngine
  private sapIntegration: SAPPricingIntegration
  private auditLogger: PricingAuditLogger

  async calculatePrice(context: PricingContext): Promise<PricingResult> {
    // Chain of responsibility pattern for pricing rules
    const basePrice = await this.getBasePrice(context.product)
    const seasonalPrice = this.applySeasonalAdjustments(basePrice, context)
    const volumePrice = this.applyVolumeDiscounts(seasonalPrice, context)
    const finalPrice = await this.validateWithSAP(volumePrice, context)
    
    await this.auditLogger.logPriceCalculation(context, finalPrice)
    return finalPrice
  }
}
```

```markdown
# Domain Glossary - Supply Chain Management

## Business Terms
- **Reorder Point (ROP)**: Inventory level triggering automatic reorder
- **Safety Stock**: Buffer inventory for demand variability
- **Lead Time**: Time between order placement and receipt
- **ABC Classification**: Inventory categorization by value/importance

## Technical Patterns
- **Service Naming**: [Domain][Entity]Service (e.g., InventoryProductService)
- **Error Codes**: INV-001 to INV-999 for inventory domain
- **Logging Format**: JSON with correlationId, timestamp, severity
- **Test Structure**: Given-When-Then with descriptive names

## Integration Standards
- **SAP Connectivity**: Use SAP Cloud Connector for on-premise
- **Authentication**: OAuth 2.0 with Azure AD integration
- **Data Formats**: ISO standards for dates, currencies, units
```

#### 2. **Architecture Decision Records (ADRs)**
Document architectural decisions for consistent prompt responses.

**Example: ADR for Integration Patterns**
```markdown
# ADR-001: API Integration Patterns

## Status: Accepted

## Context
Multiple integration patterns available for SAP connectivity:
- Direct database access
- OData services
- RFC calls
- Event-driven messaging

## Decision
Use OData services as primary integration method with event-driven fallback.

## Consequences
- Consistent API patterns across services
- Better maintainability and testing
- Reduced coupling with SAP internals

## Implementation Guidance
```typescript
// Standard integration pattern
class SAPIntegrationService {
  async fetchEntity(entitySet: string, filters?: string): Promise<any[]> {
    const url = `${this.baseUrl}/${entitySet}`
    const response = await this.odataClient.get(url, { $filter: filters })
    return response.data.value
  }
}
```
